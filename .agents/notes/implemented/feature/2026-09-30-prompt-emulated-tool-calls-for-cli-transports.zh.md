# Agent Note：CLI 传输层用提示词模拟工具调用

Status: implemented

[English](2026-09-30-prompt-emulated-tool-calls-for-cli-transports.md) | 中文

## 问题

[把厂商 CLI 当作模型传输层](2026-09-30-vendor-cli-as-model-transport.zh.md)让 Claude 订阅在 Harness 内部有了一条模型路由，且没有任何令牌离开 CLI。但它无法服务一个聊天回合。Claude Code 既不提供传入调用方工具定义的方式，也没有「上报工具调用但不执行」的模式，因此该路由拒绝任何携带 `GenerateOptions.tools` 的请求——而几乎每个真实回合都携带它们，压缩也一样。选择器里那一项存在，却答不了用户发给它的第一条消息。

有三种机制能填这个缺口，只有一种把循环留在 `agent-loop`：通过 MCP 把 Harness 的工具交给 CLI，会把迭代与停止决策搬进 Claude Code；取出 CLI 的 OAuth 授权去调厂商 API，会把上一条决策拒绝过的风险全部揽回来；把工具定义当作提示词文本携带，则保住 Harness 的循环、守卫、审批与压缩，只要求模型以文本形式上报一次调用。

## 决策

**CLI 传输层把请求的工具定义放进系统提示词，并把模型的文本调用解析回真正的 `tool-call` 块。** `@deepseek-ai/dsh-llm-claude-cli` 在 `toolCalls: 'prompt'` 下这样做，这也是默认值；`'refuse'` 为想要旧行为的部署保留它。Base Bundle 行仍为 `disabled: true`，因此对不主动启用的用户没有任何变化。

机制由 `src/emulate.ts` 拥有。前言是一整块固定文本——上报一次调用的约定、路由将强制的两个上限，以及每个已声明工具连同它的 `description` 与 `parameters` schema——由 `PREAMBLE_TEMPLATE` 标识，并由一个测试逐字钉住。它不是可调项：正是它的措辞让回复可被解析。上限与重跑预算**是** `Config` 字段，因为一次回复可携带多少调用、单个调用可以多大、以及一个部署愿意为多少次纠正性重跑付费，都是部署层面的选择。

有四项后果重要到必须在设计时就顾及，而不是事后发现。

**回复是不可信文本，因此它违反约定的每一种方式都有唯一一个具名结果。** `TOOL_CALL_TRUNCATED`、`TOOL_CALL_MALFORMED`、`TOOL_CALL_UNKNOWN_TOOL`、`TOOL_CALL_TOO_LARGE`、`TOOL_CALL_LIMIT` 各自说明这次回复做了什么、以及一次改正后的回复必须做什么。调用绝不会被悄悄丢掉、凭空编造或擅自修补。被拒之后最多发起 `toolCallRetries` 次纠正性重跑，把请求连同一段指明错误的提示重新发出；这种替换只在第一个文本块或工具调用块交出去之前才可能，因为在那之后调用方已经看到了会与第二次运行相矛盾的输出，被拒就成为终止性的 `finish`。

**前言是新的模型可见输入，所以它入日志。** 模拟请求的每一次 CLI 运行都在运行**之前**追加一条 `llm/cli-tool-emulation` 事件：路由、模型、模板标识、前言长度、已声明的工具名、这是第几次运行，以及重跑所携带的纠正提示原文。前言文本本身不入库，因为它是模板与请求头中工具 schema 的纯函数，而这两样日志已经持有。请求指向一个存储无法访问的会话时，它以 `EMULATION_NOT_LOGGABLE` 失败，而不是在无日志的情况下去做模拟。该事件是一个新根，不需要改动 `SESSION_FORMAT_VERSION`。

**schema 一致性留在工具层。** 这个边界检查结构——JSON 对象、已声明的工具名、对象形式的 `arguments`、大小与数量上限——但违反工具 `parameters` schema 的 `arguments` 按原样转发。Harness 的工具层已经校验它们，并把违规作为工具结果报告给模型，这与其他每个 provider 走的纠正路径相同；在这里再放一个校验器等于再放一套分歧，还会把一个模型适配器耦合到工具运行时上。

**被接受的调用之后的文本被丢弃，循环的系统提示词被提升。** 没有让出控制权手段的模型会在调用之后继续写并编造结果；前言禁止这样做，路由把它丢掉并记录被丢弃的长度。另外，由循环构造的请求不设置 `GenerateOptions.system`，而是把提示词放在打头的 system 角色消息里，因此该消息被提升进 `--system-prompt`：不提升的话，Harness 的提示词会以一个带标签的段落出现在用户回合内部，而 Claude Code 自己的提示词仍压在它上面。

## 考虑过的替代方案

**用 CLI 的 `--json-schema` 结构化输出约束回复。** 一个 `{text, tool_calls[]}` 的 schema 能让回复在构造上就是合法 JSON。实测后否决：以 Claude Code 2.1.285，同一请求的 prompt token 从 1,100 涨到 9,015，跨五个内部回合，因为 CLI 是靠跑自己的工具循环来满足 schema 的，而模型随后报告它没有可用的工具。

**在闭合围栏处使用 stop sequence。** 那会直接结束生成，而不是丢弃编造的文本。CLI 不提供 stop sequence 参数。

**缓冲整个回复，使任何被拒都能重跑。** 那会让纠正性重跑在所有情形下都可行，而不只是在第一个块之前。否决：模拟回合就是每一个 agent 回合，缓冲会为了保护实测模型很少踩到的那条路径，而永久取消聊天的增量流式。

**最后一个调用块闭合后立即终止子进程。** 那会省下为编造的续写付的钱。否决：CLI 只在终止性的 `result` 消息里报告用量与停止原因，这么做等于用精确的 token 计账去换几个输出 token。

**在这里按工具 schema 校验 `arguments` 并重跑。** 上文已否决：它复制了仓库里唯一的 JSON-Schema 校验器，并会让一个模型适配器依赖工具运行时及其 peer。

## 后果

Claude 订阅可以服务主聊天模型。Harness 保住了它的循环、守卫、审批与压缩，带工具的回合能走通：面对已安装的 CLI，`sonnet` 通过一次真实的 `read_file` 调用读取 `/etc/hosts`，随后依据交给它的工具结果作答。

它要付 prompt token，也依赖模型的顺从。以 `haiku` 实测，固定约定文本是 289 个计费 prompt token，五个现实工具声明各约 82 个；其中只有约定文本那一块是接受 `tools` 字段的 provider 不会收费的额外开销。没有任何东西约束回复，因此弱模型是一个真实的失效模式：`haiku` 有时把正确的块包在多余的 `<function-calls>` 标签里，它们能被解析但会作为 assistant 文本留存，而 `sonnet` 每次都干净。这条路由值得配强模型启用，不值得配弱模型。

围栏处流式会停顿：一段文本只要不可能开启围栏就立刻放行，所以普通回答是流式的；但一旦回复开启了围栏，在该块闭合之前不再显示新内容。纠正性重跑会把整个请求重发一遍，被放弃的那次运行的 token 用量不会上报，因为回复一旦被拒，它的子进程就立刻被终止——会话日志会记录那次运行发生过。

对不主动启用的用户没有任何变化：该行仍以禁用状态发布，启用它只需一个按 id 的覆盖。
