# Agent Note: 用消费者订阅账号驱动主模型

Status: proposed

[English](2026-09-30-subscription-account-main-model.md) | 中文

## Problem

仓库所有者希望已登录的消费者订阅账号——Claude Pro 或 Max、ChatGPT 或 Codex——能够驱动主聊天模型，而不只是运行委派的 Claude Code 与 Codex 工作。[官方 CLI AI 账号决策](../../implemented/feature/2026-09-29-official-cli-ai-accounts.zh.md)正是拒绝了这一点：它把令牌用于主模型的包从所有组合中移除，只保留针对已登记的配置目录启动厂商自己的 CLI 这一条访问订阅的途径。支撑那次拒绝的外部事实没有任何变化；改变的是所有者给出的答案。

## Proposal

2026-09-30，仓库所有者决定允许已登录的消费者订阅账号服务主聊天模型，从而推翻[官方 CLI AI 账号决策](../../implemented/feature/2026-09-29-official-cli-ai-accounts.zh.md)中关于主模型的那一半。该决策的其余部分保持不变——AI 账号是一个登记在案的官方 CLI 配置目录、每个账号一个目录、只存储元数据、以及通过 Claude Code 与 Codex 提供者 Bundle 进行委派——其记录的理由、备选方案与后果均按原文保留；它在状态一侧带有指向本决策的互链。

截至本决策，没有任何实现。没有任何包、Profile 行、Config 字段、凭据存储记录或测试把订阅 OAuth 令牌路由到主模型，先前决策移除的那些包也没有恢复。以下记录的是这个决定、实现它需要什么，以及所有者接受了什么。

实现它要求 Harness 从那个 CLI 的私有存储中读出一份颁发给其他客户端的长期 OAuth 授权、持有它，并向厂商令牌端点刷新它。届时将存在两份需要撤销的授权副本——官方 CLI 的与 Harness 的——撤销其中一份并不影响另一份继续可用。

## Unchanged external facts

消费者订阅登录是一份颁发给厂商官方 CLI（Claude Code 或 Codex）的 OAuth 授权，既不是颁发给订阅者，也不是颁发给任意 HTTP 客户端。因此，用这份授权服务主模型要求每个请求都呈现该 CLI 的客户端标识。

`@earendil-works/pi-ai` 记录了这个标识的具体内容。在 `packages/llm/llm-pi-ai/node_modules/@earendil-works/pi-ai/dist/api/anthropic-messages.js` 中，`anthropic-messages` 的 OAuth 令牌路径发送 `user-agent: claude-cli/<version>` 与 `x-app: cli`，加上 `claude-code-20250219` 与 `oauth-2025-04-20` 两个 beta 特性，并在请求自身的系统文本之前插入一个内容为 “You are Claude Code, Anthropic's official CLI for Claude.” 的系统块。API key 路径不发送其中任何一项。这些都是第三方依赖中固定写死的字面量，而非厂商文档化的 API。

## Alternatives considered

**保留只做委派的决策。** 订阅凭据从不经过 Harness 代码、日志或存储，每个登录都只在一处可撤销，下文的风险也都不会出现；这正是先前决策选择它的原因。它落选的原因是：它让主聊天模型留在别的路由上，而让订阅驱动主模型恰恰是所有者唯一想要的事。

**用 Anthropic 或 OpenAI API key 运行主模型。** API key 颁发给其持有者，不呈现任何其他客户端的标识，不与任何订阅条款冲突，也不需要私有存储；`@deepseek-ai/dsh-llm-pi-ai` 已经带有可以承载它的 `anthropic-messages` 与 `openai-completions` 路由。它落选的原因是：它不使用所有者已经持有的订阅，而这正是本决策的目的。

**默认关闭，并由一个显式选择启用的 Config 字段控制该能力。** 默认关闭的字段把风险限制在主动启用它的安装上，而本仓库要求任何随部署变化的选择都用经过校验的 Config 字段表达，因此它是实现时的一项条件，而不是本决策的替代方案。作为对下文风险的回答，它落选了：这个字段决定谁启用该能力，而不决定请求是否呈现其他客户端的标识，也不决定订阅条款是否被冲突。

## Acceptance criteria

没有任何实现，因此今天没有任何东西验证这个决定。这就是本决策指明的覆盖缺口：反转已被记录但未被构建，已发布的行为仍是先前决策所描述的只做委派的行为。

如果该决定被实现，完成意味着：

- 拥有该能力的插件上有一个经过校验、默认关闭的 `Config` 字段控制该路由；字段关闭时不注册任何由订阅支撑的主模型路由，并有单元测试固定两种状态。
- 字段开启而该种类没有已登录账号时，主模型请求以具名的缺失凭据错误显式失败，而不是回落到别的路由。
- 该授权从不出现在会话日志、转录、溢出文件、交付物或错误消息中，并针对一次成功请求与一次刷新失败分别断言。
- OAuth 路径的首个系统块是模型可见输入，因此由一个会话事件承载、由一份无密钥录制会话快照覆盖，两个 SDK 的期望输出也在同一次改动中更新。
- 选择启用的界面在用户启用它的位置说明：请求将呈现厂商官方 CLI 的标识，且承担风险的账号是用户自己的账号。
- 一条[升级指南](../../../skills/dsh-create-upgrade-guide/SKILL.md)条目记录每一项外部可感知的变化，包括任何设置页面或默认模型的变化。
- 在真实订阅账号上的真实登录与真实主模型请求仍是人工检查；它们不自动化，CI 也不执行它们。

## Risks

把第三方客户端呈现为厂商的第一方 CLI，是所有者接受的核心内容：每个请求都在其 user-agent、`x-app` 头、beta 特性与首个系统块中声称自己是厂商的官方 CLI，而这个声称并不真实。

该能力与两家厂商的消费者订阅条款相冲突，这些条款约定订阅只在厂商自己的客户端中使用。暴露的账号是用户自己的账号，因此现实的处罚是该订阅账号及与之绑定的其他内容被停用或终止；Harness 没有自己的账号来承担这一后果。

这条路径依赖官方 CLI 的私有令牌存储，以及没有任何厂商文档化的客户端标识。两者都可能在任何时候未经通知地改变，因此该能力可能在任何一次 CLI 或 API 更新时失效，包括会话中途失效，也包括因用户并未选择的更新而失效。

Harness 会成为一份颁发给其他客户端的长期授权的持有者与刷新者。届时将存在两份需要撤销的授权副本，撤销 CLI 那一份并不会阻止 Harness 那一份。

所有者换来的是：已经付费的订阅在 Harness 自己的 agent loop 内服务主聊天模型，既没有单独的按令牌 API 计费，也不委派给 Claude Code 或 Codex 子进程。

本决策不授权任何关于其他厂商受认可的第三方登录的事项。主模型自己的登录是一个独立决策——[用 Coteccons SSO 驱动主模型](../../implemented/feature/2026-09-30-coteccons-sso-entra-main-model.zh.md)——新增、修改或移除一条受认可的路由都不在本决策范围内。
